## Why

The capture bundle is the one contract every source produces and the library consumes ([design.md, capture
bundle](../../design.md#capture-bundle-the-one-contract-every-source-produces)). The club's archive needs archival
description on top of it: where an item sits (collection → series → item → page), what it is, when, and in what
physical form. It's first on the critical path because D06, D07, D10 and D11 all build on it.

## Inputs

- design.md's bundle layout (`manifest.json`, `raw/`, `pages/`, `quick/`, `quality.json`).
- portal.md's hierarchy (collection → series → item → page) and the fields policies need (date, type, tags,
  rights).
- D01's draft series list (names only, for the example config; the spec doesn't depend on it).

## Outputs

- `docs/capture-bundle.md`: the spec, v1.
- `schemas/capture-bundle-v1.json` (JSON Schema).
- `athena/bundle/`: read, write and validate bundles; EDTF date parsing; a separator-sheet decoder interface used by
  D07.
- `athena bundle validate <dir>` CLI.
- Synthetic example bundles under `tests/fixtures/bundles/` (generated by a script, made-up content).

## The spec (to be written up in full in `docs/capture-bundle.md`)

**One bundle = one item** (a yearbook, a newsletter issue, a clipping, a photo, a folder of minutes for one
meeting). A capture session produces many bundles.

```
<bundle-id>/                 bundle-id: a ULID (sortable, no personal data)
  manifest.json
  raw/001.<ext>              the master, exactly as captured: HEIC/DNG/JPEG (iPhone, PIXY) or TIFF (flatbed)
  pages/001.jpg              cropped and deskewed, full resolution, JPEG q95 (or PNG)
  quick/001.json             Apple Vision tier-0 lines (optional; added by Sieve when missing)
  quality.json               per page: sharpness, glare, evenness, skew, measured ppi and how it was measured
  slip.jpg                   optional photo of a handwritten item slip, to help describe the item later
```

`manifest.json` (abridged):

```json
{
  "bundle_version": 1,
  "id": "01JD7…",
  "created_at": "2026-12-08T14:03:11-05:00",
  "station": {"name": "desk-iphone", "software": "athena-capture", "version": "0.1.0"},
  "source": "camera",
  "device": {"make": "Apple", "model": "iPhone …"},
  "describe": {
    "collection": "archive",
    "series": "newsletters",
    "item": {
      "title": "Newsletter, spring issue",
      "date": "1962-04",
      "type": "newsletter",
      "creator": "",
      "physical": {"container": "box 1, folder 3", "format": "mimeograph", "extent": "4 pages", "condition": ""},
      "language": "en",
      "notes": ""
    }
  },
  "pages": [
    {"n": 1, "side": "recto", "raw": "raw/001.heic", "raw_sha256": "…", "page": "pages/001.jpg",
     "page_sha256": "…", "width": 5200, "height": 6730, "ppi": 610, "ppi_source": "scale", "kind": "text"}
  ]
}
```

- **Dates are EDTF** (Library of Congress Extended Date/Time Format, levels 0–1): `1962`, `1962-04`, `1962~`
  (circa), `1962?` (uncertain), `1960/1969`, `196X`. Policies (D11) compare against the earliest and latest
  possible year.
- **Series and collection are slugs** defined in the library's config (not in the bundle schema). An unknown slug
  is a warning, not an error; the library files the item under "unsorted".
- **Type** comes from a vocabulary in the library's config (example: yearbook, program, newsletter, flyer,
  minutes, letter, directory, clipping, photograph, other).
- **`kind`** per page: `text`, `photo`, `handwriting`, `mixed`, `blank` (versos), so Sieve can skip OCR or pick a
  tile budget and the site can label image-only pages.
- **No visibility in the bundle.** Visibility is set in the library, where everything starts private.
- **No personal data in names or paths**: bundle ids are ULIDs; operator is a station login, not a person's name.

## Steps

1. Write `docs/capture-bundle.md` and the JSON Schema.
2. `athena/bundle/`: dataclasses, `read(dir)`, `write(dir, …)` (atomic: write to `<id>.partial/`, fsync, rename),
   `validate(dir)` (schema, every file present, every sha256 matches, EDTF valid, pages numbered 1..n, no extra
   files).
3. EDTF subset parser returning `(earliest, latest)` dates.
4. `athena` CLI entry point with `bundle validate`.
5. A fixture generator (`tests/fixtures/make_bundles.py`) that builds bundles from `gen_testset.py` pages.

## Acceptance criteria

- The spec, schema and code agree: every example in the spec validates; the fixture bundles validate.
- `validate` rejects: a missing file, a changed byte (sha256 mismatch), a bad EDTF date, pages out of sequence, an
  extra file, a `.partial` directory.
- EDTF parser handles every form listed above and rejects malformed input.
- Works on Linux and macOS; no dependency beyond `jsonschema` (MIT) and the standard library.

## Test plan

pytest: round-trip write → read → validate; one test per rejection case; EDTF table-driven tests; property test
that any written bundle validates.

## Privacy and rights

- [ ] Fixtures are synthetic; no real names, addresses or images.
- [ ] The spec says where personal data may appear (inside `describe`, never in ids, filenames or paths).
- [ ] Rights fields are not in the bundle; rights are set in the library (D11), where the club decides.
